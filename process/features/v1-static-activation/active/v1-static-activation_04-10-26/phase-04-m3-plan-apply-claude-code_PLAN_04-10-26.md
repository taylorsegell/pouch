## Overview

Milestone M3 is the first milestone that mutates user-owned destinations. It adds the adapter trait and the `claude_code` adapter, typed-path filesystem operations behind a public `FsOps` seam, a pure `plan::diff`, the journaled `apply` (receipt, history, project lock), journal-based `resume` and `rollback`, and the commands `add`, `rm`, `use`, `deactivate`, `resume`, `rollback` with SES-1 and SES-2 output and the global flags `--project`, `--target`, `--yes` (spec section 10 M3; spec 4.7 to 4.10, 2.4, 2.5, 5, 7; PRD 7.3, 7.6, 7.7, 7.8, 11). Estimated 3 to 4 days (spec 10). It is the highest-risk milestone of product Phase 1: it creates symlinks and copies in a project, deletes only what the receipt proves is tool-owned, and must survive interruption.

Product Phase 1, tier 3 (mutation and recovery for claude-code). Risk class: schema/data migration or destructive data mutation (orchestration.md High-Risk Execution Handoff); also a trust boundary (journal, receipt, and skill names are untrusted input to deletes).

How to read this plan: "Premise Verification" records every "spec says" claim the INNOVATE step made without re-reading the text, checked against the actual spec and PRD text and against probes run on 2026-10-05; "Decisions Locked" are fixed by INNOVATE (letters a to o, plus the orchestrator exit-code call); "Plan-Level Decisions" (P1 to P30) were made at this PLAN-SUPPLEMENT inside those bounds; "Module Specifications", the "CLI Contract", and the "Test Inventory" remove every remaining design choice. ## Decisions Locked (INNOVATE 2026-10-05; apply as written, subject to Premise Verification)

| # | Decision |
|---|---|
| a | Continue past a step failure. Write-ahead journal: an fsynced `started` record before each operation, then `done`, `failed`, or `skipped`; the receipt is written once at the end with the applied subset and `last_op_id`; failed steps stay in the journal for resume and rollback; a crash between the receipt write and the journal delete is detected by `receipt.last_op_id == journal.op_id` and finalized, never replayed. Exit code 7 (apply failed) for any failed or skipped step, with a structured per-entry payload; 6 conflicts; 10 interrupted; 11 locked; each with a payload. |
| b | Lock first (non-blocking, exit 11) in every mutating command, held across the prompt. `selection.yaml` is written atomically after the confirmation and before the apply, under the lock. Refused, declined, and no-TTY-refused commands write no selection. |
| c | Per-target state: `.unam/<target>/applied.json`, `journal.jsonl`, `history/`, `trash/`; one project-wide `.unam/lock`; each file carries a version field (spelled `version`, V2). |
| d | `add` and `rm` store the qualified `SkillId`. `rm X` drops X from `add` and, if a bundle supplies X, appends X to `remove`; `rm` of an unselected X errors with no change. `use B --replace` sets `bundles` to `[B]` and clears `add` and `remove`; `use B --add` appends B idempotently. `deactivate` clears the whole selection of the target. `--all` means all targets (same as the default in M3). History stores `selection_before` and `selection_after`. |
| e | A mutating plan with no TTY, or with `--json`, and no `--yes`: refuse with exit 2, remedy "pass --yes", the plan in the payload, nothing changed. An empty plan exits 0 "no changes" without a confirmation. |
| f | `std::fs::File::try_lock`, no `fs4`. The lock file holds one JSON line `{pid, started_at, command}`; `Locked { pid: Option<u32> }`; the lock file is never deleted. `rust-version = "1.89"` in the workspace manifest. |
| g | Sealed `Writable` trait for `DestPath`, `StatePath`, `ToolPath`; `SourcePath` does not implement it; `fsops` write functions are generic over `Writable`; the raw `&Path` writer is private; the five existing `write_atomic` callers migrate to `ToolPath` (selection IO uses `StatePath`); a `compile_fail` doctest for `SourcePath` plus a compiling doctest of the same snippet with `StatePath`; `SourcePath::as_path` becomes `pub(crate)` and a test greps `fsops` for it; `write_atomic` also fsyncs the parent directory. |
| h | M3 never emits `WriteGenerated`. Receipt entries are `Entry::Skill` or `Entry::Other(serde_json::Value)`; unknown top-level receipt fields are preserved; carry-forward is byte-identical; a round-trip test proves it. |
| i | Destination names are validated: non-empty, no `/`, `\`, NUL, or control character, not `.` or `..`, at most 255 bytes. Failure is a plan conflict `invalid-name` (blocking, V9). `DestPath::join_child` accepts a single `Component::Normal` only. |
| j | Detection `Absent` defaults the target to `claude-code`, with the plan header text "not detected; .claude/skills will be created". The receipt records `created_dirs`; `deactivate` removes them with `rmdir` only, and only when empty. |
| k | Plan steps: `Add`, `Remove`, `DropOrphan { id }`, `UpdateProvenance { id, new }`; unchanged entries carry forward. Provenance is sorted and deduplicated. `selection_hash` is blake3 of the canonical JSON of the normalized selection (prefix per V4, provenance shape per V5). |
| l | Enterprise scan roots live in `Dirs` (`paths.rs`) with real defaults; tests override them through the existing `Dirs` environment map (P14). |
| m | History `.unam/<target>/history/<op_id>.json`, `op_id = {unix_millis:013}-{8 hex}` generated at plan time and stored in the journal; the first apply has `receipt_before` null; an entry holds `selection_before`, `selection_after`, `receipt_before`, `receipt_after`; prune to 20 after the new entry is durable, touching only files matching the `op_id` pattern; a prune failure is a warning. |
| n | `remove_owned(dest, &OwnedExpectation { strategy, source, tree_hash })`. Symlink: lstat is a symlink and `readlink` equals the expected text, re-check, unlink, never follow. Copy directory: verify the hash, rename into `.unam/<target>/trash/<op_id>/`, re-verify, delete by manifest walk, then `rmdir` bottom-up; on a mismatch rename back or leave in trash and report. A failed check skips and reports `Skipped { modified, foreign, missing }` and deletes nothing; `missing` drops the receipt entry; `modified` and `foreign` release ownership and are reported. Never `remove_dir_all` on a destination; `remove_dir_all` only on our own unique temp path after lstat shows a real directory. `EXDEV` on the rename-aside: fail closed, skip, report. |
| o | `copy_tree` copies into a unique temp sibling `.unam-tmp-<op_id>-<name>`, refuses links that leave the skill and special files, re-hashes against the catalog hash, then renames into place (V8 for the empty-directory case). The symlink strategy uses `symlink(2)` at the final path (an existing path is never overwritten). |
| x | Orchestrator call: exit code 7 for partial failure and for skips (decision a). |

Supporting designs, all adopted and specified below: minimal M3 `observe` shared with `remove_owned`; an owned entry still selected but unresolved because its source is unreachable is carried plus a warning, never removed, while an unresolved added reference blocks with nothing written; `deactivate` plans from the receipt alone; names are reused only after Removes (Removes run before Adds, keyed by destination name, and a skipped Remove makes the later Add skip with `dest-occupied`); the journal is untrusted input (resume and rollback re-derive every destination path from the destination root plus a validated name and re-verify every removal; steps that started without a terminal record are resolved by observing the disk); a torn final journal line is tolerated; a destination root that resolves outside the project root is a conflict and nothing is written; the "changes nothing" assertions of AC-22 and AC-53 exclude `.unam/lock`; `GITIGNORE_LINES` gains the lock and the per-target paths.

| P4 | State layout and formats. `StateDir { root, target }` yields `<root>/.unam/<target>/applied.json`, `journal.jsonl`, `history/<op_id>.json`, `trash/<op_id>/`, and `<root>/.unam/lock`. Receipt, history, and journal formats are fixed in the `state.rs` spec. | Decisions c, m; V2. |
| P5 | Lock. `.unam/lock` is created if absent (creating `.unam/` first), opened read-write, locked with `try_lock`; only after success is the file truncated and the one-line JSON `{"pid":N,"started_at":"...","command":"add"}` written. A contender that gets `WouldBlock` reads the line best-effort (a torn or empty line gives `pid: None`) and returns `Locked`, never writing the file. The lock is held by a guard struct for the whole command (including the prompt) and released when it drops. The file is never deleted. | Decisions b, f. |
| P6 | Receipt rules. `selection_hash` = `Hash::of_bytes` of the compact canonical JSON `{"strategy":"<effective>","bundles":[...],"add":[...],"remove":[...]}` of the target selection after the edit (arrays in stored order, stored texts as written), giving `blake3:<hex>`. Receipt entries are written sorted bytewise by `dest` (other entries keep their relative order after the skill entries). `Entry::Skill` carries unknown extra fields (flattened map). A receipt skill entry whose `dest` is not exactly `<adapter destination>/<name>`, or whose name fails P3, is treated as `Entry::Other` for classification (carried, never touched) with a warning `receipt-entry-ignored`. | Decisions h, k; the receipt is untrusted. |
| P7 | `plan::diff` classification (exact table in the `plan.rs` spec): Owned means the observation matches the receipt (symlink link text equals `source_path`; copy hash equals `tree_hash`). Desired and Owned with equal strategy and provenance: carry; provenance differs: `UpdateProvenance`. Desired, receipted, observation missing: `Add` (repair). Desired, receipted, observation present but not Owned: conflict `modified-at-dest`. Desired, not receipted, destination present: conflict `foreign-at-dest`. Receipted, not desired, not carried: Owned gives `Remove`; missing gives `DropOrphan(missing)`; present but not Owned gives `DropOrphan(modified)` (ownership released, file untouched). Strategy or id change at an Owned destination: `Remove` then `Add`. Two desired entries with one name: conflict `duplicate-name`. Every conflict blocks (exit 6). Step order: Removes, DropOrphans, Adds, UpdateProvenances; each group in a fixed order. | Spec 4.8 refined; V7, V9. |
| P8 | `observe` (M3 minimal): `observe_one(dest_child, want_hash)` returns Missing, Symlink { target text, resolves }, Dir { tree_hash when asked }, File, or Other, using `symlink_metadata` only; `observe(...)` covers the union of desired names and receipt destination names, computes the tree hash only for names whose receipt entry has strategy copy, classifies the destination root (P3), and lists shadow candidates (a same-named entry holding `SKILL.md` in an enterprise or user scan location). M4 promotes it into `verify`. | Supporting design; keeps `diff` pure. |
| P9 | Apply semantics. Order: lock, journal check, selection write, `begin` record (atomic file with the whole plan and `receipt_before`), then every step in order, never stopping at a failure. - `pub trait FsOps` and `pub struct RealFs` (P2). Behavior of `RealFs`:
  - `write_state` is `write_atomic`; `append_state` opens with `create` and `append`, writes the bytes, `sync_all` (the caller supplies the trailing newline); `remove_state` unlinks a file (`NotFound` is ok) then fsyncs the parent; `remove_state_dir_if_empty` is `remove_dir` ignoring `NotFound` and `DirectoryNotEmpty` (returns whether it removed).
  - `create_dir(dir: &DestPath) -> Result<bool>`: non-recursive `create_dir`; `Ok(true)` when created, `Ok(false)` when it already is a real directory (`symlink_metadata`), error when the path exists as anything else. `rmdir_if_empty`: `symlink_metadata` must show a real directory (a symlink or file is `Ok(false)`, never followed), then `remove_dir`; `DirectoryNotEmpty` and `NotFound` give `Ok(false)`.
  - `symlink_dir(src, dst)`: `src.as_path()` must be absolute; `std::os::unix::fs::symlink(src, dst)` creates the link at the final path; `AlreadyExists` is returned as an IO error (never overwritten); an `Unsupported` error maps to `SymlinkUnsupported`; non-unix returns `SymlinkUnsupported` (P27). Does not create parent directories.
  - `copy_tree(src, dst, tag, expect)`: (1) `dst` must not exist (`symlink_metadata` NotFound), (2) temp path `<dst parent>/.unam-tmp-<tag>-<name>` must not exist, (3) scan the source skill directory with an own recursive `read_dir` pruning names in `SKILL_SKIP_NAMES`; every entry must be a directory, a regular file, or a symlink, anything else is `CopyRefused` ("special file"), (4) create the temp directory, copy regular files with `fs::copy` (permission bits preserved), `sync_all` each copied file, create directories (set their source permission bits after their children are copied), (5) for each symlink: `read_link`; an absolute target or a target whose lexical resolution (`..` popping against the skill root) leaves the skill root is `CopyRefused` ("link leaves the skill directory"); otherwise recreate the link with the same target text; also refuse when the link exists and its canonical resolution is outside the canonical source skill directory (chains through other links), (6) `tree_hash(temp, SKILL_SKIP_NAMES)` must equal `expect` else remove the temp directory and return `SourceChanged`, (7) check `dst` is still absent (V8: this is the only guard against an empty directory appearing in the window) and `rename(temp, dst)`; on any error after step 3 remove the temp directory with `remove_own_temp_dir`; fsync the parent directory best effort; returns the verified hash. The source tree is only read.
  - `remove_owned(dst, expect, trash)`: exact algorithm in the `fsops` Removal Rules below.
  - `restore_owned(dst, expect, trash, source, tag)` returns `RestoreOutcome`: `dst` must observe Missing (else `NotRestored("dest-occupied")`); copy strategy: when the trash copy exists as a real directory whose tree hash equals `expect.tree_hash`, `rename` it back to `dst` and fsync the parent (`Restored`), else when `source` is given `copy_tree(source, dst, tag, expect.tree_hash)`, else `NotRestored("content-not-recoverable")`; symlink strategy: when `source` is given `symlink_dir(source, dst)` (`Restored`), else `NotRestored("source-unavailable")`. The caller (rollback) passes a `source` only after re-deriving it from the live catalog and checking that it equals the recorded one.
  - `remove_own_temp_dir(path)` (private, the single `remove_dir_all`, P30): requires the file name to start with `.unam-tmp-` and `symlink_metadata` to show a real directory.

Removal Rules (`remove_owned`; decision n; every mismatch deletes nothing):

1. `observe_one(dst, want_hash = strategy is copy)`.
2. Missing: `Skipped(Missing)`.
3. Symlink strategy: observation must be a symlink whose link text equals `expect.source` exactly, else `Skipped(Modified)` when it is a symlink with another text and `Skipped(Foreign)` for a directory, file, or other. If it matches: observe again, require the same link text, then `remove_file(dst)` (unlinks the link, never its target): `Removed`; a mismatch on the second look is `Skipped(Modified)`.
4. Copy strategy: observation must be a real directory whose tree hash (with `SKILL_SKIP_NAMES`) equals `expect.tree_hash`, else `Skipped(Modified)` for a directory with another hash and `Skipped(Foreign)` for a symlink, file, or other. If it matches: create `trash` (`.unam/<target>/trash/<op_id>/<name>` parents), `rename(dst, trash)` (error kind `CrossesDevices` gives `Skipped(CrossDevice)` and nothing moved), re-hash the trash copy; a mismatch moves it back when `dst` is still absent (else leaves it) and returns `Skipped(Modified)`. When the hash still matches: delete the manifest (G9): an lstat walk of the trash copy that prunes every name in `SKILL_SKIP_NAMES` (the same skip list the hash used, so nothing the hash did not cover is deleted: a `.git` or `.DS_Store` entry is never descended into or listed); `remove_file` each regular file and symlink the walk lists, never following; separately, an entry named `.DS_Store` is unlinked only when lstat shows a regular file, and any other `.DS_Store` entry (a directory with content, a symlink, anything else) and any `.git` entry is residue and is left untouched; then remove directories bottom-up with `remove_dir` from the same pruned lstat walk (a `DirectoryNotEmpty` marks residue, not an error), then `remove_dir(trash)`, and `remove_dir(trash/<op_id>)` when empty. Result `Removed`, or `RemovedWithResidue { trash }` when anything (for example a `.git` directory or a `.DS_Store` directory inside the copy) is left in the trash directory; unlisted content is never deleted.

### `plan.rs` (new; spec 4.8; P6, P7, P8)

Types: `Step` (`Add { n, id, name, strategy, source: PathBuf, tree_hash: Hash, provenance }`, `Remove { n, id, name, expect: OwnedExpectation }`, `DropOrphan { n, id, name, reason: OrphanReason }` with `OrphanReason::{Missing, Modified}`, `UpdateProvenance { n, id, name, provenance }`, `RemoveDir { n, dir: String }` (G3: remove a directory this tool created, only when empty; `dir` is a project-relative string, never a path)), each with `n()`, `name() -> Option<&str>` (`None` for `RemoveDir`), `op()` (`add`, `remove`, `drop_orphan`, `update_provenance`, `remove_dir`). `StepOutcome` (`Done`, `Failed { code, message }`, `Skipped(SkipReason)`) and `StepResult { n, op, id, name, dest, outcome }` are DEFINED in `plan.rs` (G8b: `build_receipt` lives here and takes `StepOutcome`, so the types must exist at E1; `apply.rs` uses and re-exports them). `Conflict` (`ForeignAtDest { dest, found, source, id }`, `ModifiedAtDest { dest, id, found }`, `DuplicateName { name, ids }`, `InvalidName { id, name, reason }`, `DestOutsideProject { dest_root, resolved }`, `DestNotDirectory { dest_root }`) with stable codes `foreign-at-dest`, `modified-at-dest`, `duplicate-name`, `invalid-name`, `dest-outside-project`, `dest-not-directory`, a one-line `message()`, and `to_json()`. `PlanHeader { root, root_how, target, dest_rel, strategy, detection_text, consumers }`. `Estimate { skills, tokens }`. `Plan { header, op_id, steps, unchanged: Vec<{id, name, dest}>, carried: Vec<{id, name, dest}>, conflicts, warnings: Vec<Diagnostic>, estimate, selection_hash, dest_dirs_to_create }` with `is_empty()` (no steps and no conflicts), `is_blocked()` (conflicts present), `removes_something()` (any Remove or DropOrphan), `to_json()` (the `plan` object of the CLI Contract).

`diff(input: &DiffInput) -> Plan` is pure (no filesystem access). `DiffInput` fields: `header`, `op_id`, `desired: &[DesiredEntry]`, `carry_ids: &BTreeSet<String>` (receipt skill ids kept without classification), `receipt: &Receipt`, `observed: &Observed`, `catalog: &Catalog`, `selection_hash: Hash`, `budget_tokens: u32`, `release_created_dirs: bool` (true only when the edit is `Deactivate`, G3). Algorithm, in order (all comparisons bytewise):

1. Names: for each desired entry `name = entry.name`; a failing `validate_dest_name` gives `InvalidName` and the entry is excluded from every later rule. Two or more remaining desired entries with the same name give one `DuplicateName` listing the ids in desired order, and those entries are excluded.
2. Root state: `Outside` gives `DestOutsideProject`, `NotDir` gives `DestNotDirectory`; when either is present the plan has no steps (conflicts only) but `unchanged`, `carried`, and warnings are still computed.
3. Receipt view: skill entries that satisfy the P6 consistency rule keyed by name; entries failing it, and every `Other` entry, are carried untouched (a warning `receipt-entry-ignored` for the failing ones).
4. Classification table for each remaining desired entry `d` (desired order); `R` is the receipt entry of the same name; every `Add` step takes `source` from `catalog.abs_path(id)` and `tree_hash` from the catalog skill; "Owned" means the observation matches `R` (symlink strategy: a symlink whose link text equals `R.source_path`; copy strategy: a directory whose hash equals `R.tree_hash`):

| R | observation | comparison | result |
|---|---|---|---|
| none | Missing | | `Add` |
| none | present | | conflict `foreign-at-dest` (found: directory, file, symlink, or other) |
| some | Owned | same id, same strategy, same canonical provenance | unchanged (carried forward byte-identical) |
| some | Owned | same id and strategy, provenance differs | `UpdateProvenance` |
| some | Owned | id or strategy differs | `Remove` of `R`, then `Add` of `d` |
| some | Missing | any | `Add` (the receipt entry is replaced when the step succeeds; no `Remove`) |
| some | present, not Owned | any | conflict `modified-at-dest` |

5. Receipt entries not matched by a desired entry and whose id is not in `carry_ids`: Owned gives `Remove`; Missing gives `DropOrphan(missing)`; present but not Owned gives `DropOrphan(modified)` (ownership released, file untouched). An entry in `carry_ids` is listed in `carried` with a warning `owned-source-unreachable` and is never removed.
6. Order: all `Remove` steps (bytewise by name), then `DropOrphan` (by name), then `Add` (desired order), then `UpdateProvenance` (desired order); `n` runs `1..` in that order. A replacement therefore removes before it adds. Created-directory removal (G3, `deactivate` only) is a final group, item 10.
7. Warnings: `shadowed` for each shadow in `observed.shadows` whose name is added, unchanged, or updated (message names the shadowing path and scope); `source-moved` (info) for an unchanged symlink entry whose link no longer resolves and whose live source path differs from `R.source_path`; `catalog-over-budget` when `estimate.tokens > budget_tokens` (ACT-12).
8. Estimate: `skills` is the count of desired entries plus carried entries; `tokens` is the sum over desired entries of `ceil((len(name) + len(description)) / 4) + 20` (description from the catalog) plus `ceil(len(name) / 4) + 20` per carried entry (spec 4.8 item 10; always labeled an estimate).
9. `dest_dirs_to_create` comes from `DestRootState::Missing { to_create }` and is non-empty only when the plan has at least one `Add`.
10. Created directories (decision j and G3; `deactivate` only): when `input.release_created_dirs` is true and, after the plan's Remove and DropOrphan steps, no valid skill entry of the receipt remains (receipt skill entries that failed the P6 consistency rule, and carried entries, count as remaining), the plan appends one `RemoveDir { dir }` step per entry of `receipt.created_dirs`, in reverse creation order (deepest first), after every other step. A `created_dirs` string is a claim, never a path: it is used only when it equals one of `fsops::dest_prefixes(header.dest_rel)`; any other string is ignored with the warning `receipt-entry-ignored`. The step carries only the project-relative string; the typed path is rebuilt at apply time from the matching `DestPath::ancestors()` pair, so `diff` stays pure and never touches the filesystem; whether the directory is empty is decided at apply time by `rmdir_if_empty`. A `RemoveDir` step does not count for `removes_something()` (no SES-2 caveat).

`selection_hash` and `op_id` are copied from the input. Property and unit tests first (`proptest`, default 256 cases, plus one run at `PROPTEST_CASES=1024` in G18): the classification table row by row; `diff_is_idempotent_after_a_full_apply` (AC-16); `unchanged_entries_are_carried_forward_byte_identical` (AC-17, including an `Other` entry and unknown fields); `diff_never_touches_unreceipted_or_foreign_names` (no step names a destination that has no receipt entry, no step or conflict resolution touches a foreign name); `diff_is_deterministic`; `steps_are_ordered_removes_droporphans_adds_updates`; `name_reuse_removes_before_adds`; the invalid-name, duplicate-name, outside-project, and not-directory conflicts; carried entries never removed; the estimate formula on a worked example; the over-budget warning; the `build_receipt` table (each outcome kind, sorting, `extra` and `Other` preserved, `created_dirs` union and removal by `dirs_removed`); the `RemoveDir` rows (deactivate emits reverse-order steps only when no skill entry remains, a forged `created_dirs` string such as `..` or `.claude/other` is ignored with `receipt-entry-ignored`, no other edit ever emits them). Generators draw from a pool of eight skills (one duplicate name pair across ids), random subsets in random order, random provenance from `{bundle a, bundle b, adhoc}`, random strategy; the receipt is produced by `build_receipt` (this module) over a first diff; the observed map is derived from the receipt, with random hand deletions, retargeted links, and planted foreign names; the property runs only on inputs whose plan has no conflicts.

### `apply.rs` (new; spec 4.10; P9, P10, P16)

Types: (`StepOutcome` and `StepResult` come from `plan.rs`, G8b) `ApplyReport { op_id, command, results, status (Applied, AppliedWithSkips, Partial), receipt, history_written, warnings, new_dirs, removed_dirs, removal_applied, refresh }`, `RecoverReport` (same shape plus `action`), `JournalSummary { op_id, command, target, started_at, receipt_written, steps: Vec<{n, op, name, state}> }`, `Inspection` (`Clear { notes }` or `Interrupted(JournalSummary)`), `ApplyCtx { root, adapter, state: StateDir, dest: DestPath, catalog: Option<&Catalog>, clock }`, `SelectionPrelude { command, selection_before: {existed, text}, selection_after_text, selection_after_hash }` (G11: when the selection did not change, `change::prepare` sets `selection_after_text` to exactly `selection_before.text` and `selection_after_hash` to the hash of those bytes, because the file is not rewritten; `rollback` then finds an equal hash and raises no `selection-not-restored`).

- `build_receipt(before, plan_steps, outcomes, now, op_id, selection_hash, dirs_created, dirs_removed) -> Receipt` (pure; defined in `plan.rs` and used by `execute`, `resume`, and the proptests). Rules: start from `before.entries`; `Remove` Done removes the entry with that `dest`; `Remove` Skipped with Missing, Modified, or Foreign also removes it (ownership released), any other skip or failure keeps it; `DropOrphan` removes it; `Add` Done upserts a new `SkillEntry` (`applied_at` = now, `source_path` and `tree_hash` from the step, provenance canonical, `git_commit` null, `pin` `follow`); an `Add` that did not finish changes nothing; `UpdateProvenance` Done replaces only the provenance of the entry (its `applied_at` is kept); unchanged and `Other` entries are untouched; entries are re-sorted bytewise by `dest` (others after); `applied_at` = now, `selection_hash` and `last_op_id` updated, `created_dirs` = before plus `dirs_created` without duplicates, minus `dirs_removed`, `extra` preserved; a `RemoveDir` step changes nothing by itself (only a journal `dir_removed` record drops a claim).
- `execute(ctx, plan, prelude, fs) -> Result<ApplyReport>`: (1) load the receipt (the plan was computed from it under the same lock); (1b) `apply::ensure_dest_root(ctx)` (G2): `classify_dest_root(ctx.root, adapter.destination())` immediately before the first filesystem operation of the apply; `Outside` or `NotDir` returns `Error::DestRootInvalid` and nothing is written (no journal, no directory, no receipt); (2) write `begin` as a single-line file through `FsOps::write_state` (atomic, so it is never torn); (3) for each step in order: append `started`, run it, append the terminal record, and never stop at a failure. Run rules: `Add`: first create each missing prefix of `dest_dirs_planned` write-ahead (G6c): append the `dir {path}` intent record BEFORE `FsOps::create_dir`, and when `create_dir` returns `false` (the directory already existed) append `dir_skipped {path}` so it is not counted as created; then `observe_one(child)` must be Missing, else the step is `Skipped(DestOccupied)`; then `symlink_dir` (strategy symlink) or `copy_tree(source, child, op_id, tree_hash)` (strategy copy); an error is `Failed { code: error.code(), message }`. `Remove`: `remove_owned(child, expect, trash)`; `Removed` and `RemovedWithResidue` are Done (the residue adds a warning `trash-residue` naming the trash path); `Skipped(r)` is `Skipped(r)`; an error is Failed. `DropOrphan` and `UpdateProvenance` are Done without filesystem work. `RemoveDir` (G3): find the `ctx.dest.ancestors()` pair whose string equals the step's `dir` (no match is Failed `dir-not-recognized`, nothing touched), then `FsOps::rmdir_if_empty`; on `true` append `dir_removed {path}` (the rmdir first, the claim drop second: the claim leaves the receipt only through the journal record, via `dirs_removed`); on `false` the directory stays recorded and the step is Done with the warning `created-dir-kept`; an rmdir error is Failed. Every destination path is `ctx.dest.join_child(name)`. A journal append error aborts `execute` at once with that error (no step may run without a durable `started`). (4) Outcome: any Failed step gives `Partial`; otherwise `AppliedWithSkips` when a step was skipped, else `Applied`. (5) Final sequence: build the new receipt (`build_receipt` with the journal's `dir` records minus `dir_skipped` as `dirs_created` and its `dir_removed` records as `dirs_removed`, then set `project_root` to `ctx.root`); for `Applied` and `AppliedWithSkips` write the history entry (P16), then write the receipt, then append `receipt` with outcome `clean` or `skips`, then delete the journal, then prune history (a prune error is a warning `history-prune-failed`); for `Partial` write the receipt and append `receipt` with outcome `partial` and keep the journal, writing no history entry. (6) `refresh` comes from `adapter.refresh_note(ApplyContext { dest_root_existed })` where the flag is true when `dest_dirs_planned` was empty.
- `inspect(ctx, fs) -> Result<Inspection>`: `Absent` is `Clear`; `TornBegin` deletes the journal and returns `Clear` with the note `discarded an unfinished journal (it never recorded a plan)`. For a present journal: `receipt_written` is true when the `receipt` marker exists or `receipt.last_op_id == op_id`. When `receipt_written` and no step is Failed and every step is terminal: finalize (write the history entry from the journal's `receipt_before`, `selection_before`, `selection_after_text` and the current receipt when `history/<op_id>.json` is missing, delete the journal, prune) and return `Clear` with the note `finalized a completed apply (the journal was left behind)`; this is never a replay. Every other journal returns `Interrupted(summary)` and changes nothing.
- `resume(ctx, fs) -> Result<RecoverReport>` (requires `ctx.catalog`): read and validate the journal; `apply::ensure_dest_root(ctx)` (G2; refuse before any change); when `torn_tail` is set or the journal file does not end with a newline, first rewrite the journal atomically through `FsOps::write_state` with `journal.valid_text` so that no appended record can merge with torn bytes (G6a); remove stale `.unam-tmp-<op_id>-*` entries of this operation in the destination root (lstat must show a real directory; own name pattern only; `remove_own_temp_dir`); then for each step without a terminal record (Pending, Started, Failed), in ascending `n`, append `started` and resolve it by observing the disk: `Add`: Missing gives a re-run (missing `dest_dirs_planned` prefixes are created again with the write-ahead `dir` record; source re-derived from `catalog.source_path(id)`; the skill must still exist with the planned name, else Failed `source-changed`; the symlink target text and the copy hash come from the live catalog); an observation that already matches the expectation gives Done with `how: observed`; anything else present gives `Skipped(DestOccupied)`. `Remove`: present gives a re-run of `remove_owned`; Missing with the trash copy present gives Done and a warning `trash-left`; Missing otherwise gives `Skipped(Missing)` (ownership released). `DropOrphan`, `UpdateProvenance`: Done. `RemoveDir`: a missing directory counts as removed (append `dir_removed` when the journal lacks it, then Done with `how: observed`); a present directory re-runs `rmdir_if_empty` (kept with the warning `created-dir-kept` when not empty). Then the final sequence of `execute` (step 5) with the journal's `receipt_before` and the same `op_id`.
- `rollback(ctx, fs) -> Result<RecoverReport>` (uses `ctx.catalog` when present): read and validate the journal; `apply::ensure_dest_root(ctx)` (G2; refuse before any change); remove stale temp entries; then for every step that is not `Skipped`, in descending `n`, decide by observing the disk (never by trusting the recorded state): `Add`: when the destination matches what the step would have created (symlink text equals the step `source` text; copy hash equals the step `tree_hash`) call `remove_owned`; Missing: nothing; any other content: leave it and report `rollback-left`. `Remove`: when the destination is present: nothing; when Missing call `FsOps::restore_owned` (rename the trash copy back after a hash check; recreate a symlink only when the live catalog path text equals the recorded `expect.source`; recreate a copy from the live source only when the live hash equals `expect.tree_hash`); `NotRestored(reason)` is reported as `rollback-not-restored`. `DropOrphan` and `UpdateProvenance`: nothing. `RemoveDir` (these steps have the highest `n`, so descending order runs them first and the destination root exists again before any restore): when the recorded directory is Missing, recreate it with `FsOps::create_dir` (shallowest first); present: nothing. Then remove each created directory (the journal's `dir` records minus `dir_skipped`) in reverse with `rmdir_if_empty`; restore the receipt (`receipt_before` null removes `applied.json`; otherwise rewrite its canonical text; skipped with a warning `receipt-not-restored` when the current receipt exists and its `last_op_id` is neither the journal's `op_id` nor equal to `receipt_before`'s); restore `selection.yaml` only when its current bytes hash to `selection_after_hash` (when `selection_after_hash` equals the hash of `selection_before.text` the file was never rewritten: nothing is written and no warning is raised, G11; otherwise rewrite `selection_before.text`, or remove the file when `existed` was false; otherwise a warning `selection-not-restored`); remove `history/<op_id>.json` when present through `FsOps::remove_state` (op_id validated; G6b: the final sequence writes history before the receipt, so a crash in that window must not leave a history entry describing an undone apply); delete the journal; then end with the G5 cleanup rule: `FsOps::remove_state_dir_if_empty` bottom-up over `trash/<op_id>`, `trash`, `history`, and `.unam/<target>` (each only when empty; a non-empty one stays; `.unam` itself is never removed because it holds the lock), so the whole project tree equals the start. No history entry is written. Anything left or not restored makes the CLI exit 7 with the per-step list; a rollback is repeatable after a crash because every decision observes the disk.
- Unit tests first (a local failing `FsOps` wrapper in the module counts the three destination calls; tempdir projects): a clean apply of three Adds writes journal records in order (`begin`, then `started`, `done` per step, then `receipt`), receipt, history, and no journal; - `prepare(req, fs) -> Result<Prepared>` where `Prepared { plan, tsel_before, tsel_after (None for deactivate), selection_before: {existed, text}, selection: Selection (whole file after the edit), selection_changed, warnings, receipt, adapter }`: (1) adapter and effective strategy (P17); (2) read the raw selection text (absent is `existed: false`) and load it; (3) `apply_edit` (deactivate removes the target key); (4) unless deactivating, `resolve_selection` over `tsel_after`; split problems: a problem of kind Unresolved whose canonical reference equals a receipt skill id and whose `unreachable` list is non-empty is an owned-unreachable carry (id added to `carry_ids`), every other problem blocks with the first problem's error (exit 2, 4, or 5) and every problem as a warning diagnostic; (5) load the receipt; (6) for deactivate, desired is empty and `carry_ids` is empty (plan from the receipt alone); the catalog is not loaded for deactivate (the CLI passes `Catalog::default()`, so the estimate has no descriptions and unreachable sources cannot block it); (7) `observe` the union of names; (8) `diff` (`release_created_dirs` is true only for `Edit::Deactivate`, G3); (9) set the journal selection fields (G11): `selection_after_text` and `selection_after_hash` are the rendered text and its hash when `selection_changed`, else exactly `selection_before.text` and the hash of those bytes; (10) add the warning `receipt-root-moved` (naming the old and new root) when `Receipt::root_moved` is true; (11) return. - `run(req, fs, decide) -> Result<Outcome>`: (0) `ensure_project_outside_sources(&req.config, req.root)` (G7); (1) `ProjectLock::acquire` (creating `.unam/`; it refuses a symlinked or wrong-kind `.unam` or lock, G1), then `state::check_state_layout(root, Some(target))` for the resolved target (G1); (2) `inspect` (an `Interrupted` result is `Outcome::Interrupted(summary)`, which the CLI renders as exit 10 with the summary in the payload; notes are kept as info diagnostics); (3) `prepare`; (4) conflicts present: `Outcome::Blocked` (exit 6); (5) empty plan: write the selection when `selection_changed` (rendered with `render_selection` and written through `fs.write_state`, so the fault matrix counts the write; then `register_project`, below), return `Outcome::NoChanges`; (6) `decide(&plan)`: `Refuse` gives `Outcome::Refused`, `Decline` gives `Outcome::Declined`, nothing written in either case; (7) `apply::ensure_dest_root` again (G2: the destination root may have been swapped during the prompt; a refusal here writes nothing), then write the selection when changed (through `fs.write_state`) and, when it was written, `register_project` (below); (8) `execute` (which re-checks the root once more immediately before its first filesystem operation); (9) `Outcome::Applied`. `Outcome` is `NoChanges`, `Blocked`, `Refused`, `Declined`, `Applied` (each carrying the `Prepared`, and `Applied` also the `ApplyReport`) or `Interrupted(JournalSummary)`; the lock guard is dropped when `run` returns.
- `register_project(dirs: &Dirs, canonical root path, warnings: &mut Vec<Diagnostic>)` (Gap 13; spec 4.5, "Register the root in the project index on every write"): `run` calls it immediately after every selection write (step 5 and step 7, `Edit::Deactivate` included) and never after a run that wrote no selection. It calls the existing M2 function `project::index::register(dirs, root)` (returns `Result<Vec<Diagnostic>>`); the returned diagnostics are appended to `warnings` (an existing index that cannot be read, for example a directory at the index path, comes back this way: `register` returns `Ok` carrying the diagnostic `project-index-unreadable`; they surface in the `Prepared.warnings` of the returned `Outcome`, so in the CLI warnings array). An `Err` (the atomic index write itself failing, for example a read-only data directory while the index is absent) becomes the warning `project-index-failed` (the message names the error); both codes, `project-index-unreadable` (inside `Ok`) and `project-index-failed` (from `Err`), can surface from this one call, and neither ever fails, blocks, or changes the exit code of the command: the index is a derived convenience list under the user data directory (a `ToolPath` write outside the `FsOps` fault-injection count), and the selection and apply are already durable. This is what lets M2's `projects_referencing_source` (the `source rm` guard) and `projects_referencing_bundle` see projects that M3 activated; before this fix nothing in production called `register`, because `bundle save` writes a bundle manifest and never touches the selection.
- `RecoverRequest { dirs, config, catalog, root, target: Option<TargetId>, clock }`, `resume(req, fs, decide)` and `rollback(req, fs, decide)`: `ensure_project_outside_sources` (G7, before the lock), lock, resolve the target (P12), `state::check_state_layout(root, Some(target))` (G1), `read_journal` (absent is `NoJournal`), build the step list for the confirmation, `decide`, then `apply::resume` or `apply::rollback`; outcomes `Recovered(report)`, `Declined`, `Refused`.
- Unit tests first (tempdir projects, in-process `Catalog`, `RealFs`): `apply_edit` table for every edit and error (add idempotent, add drops a matching remove, rm drops add, rm records remove for a bundle-supplied skill, rm not selected, rm dangling add by exact text, use replace, use add idempotent, unknown bundle, deactivate); `resolve_target` all branches; `resolve_root` with `--project`; owned-unreachable carry versus blocking unresolved; `run` for every `Outcome` (conflict leaves no selection and no journal, empty plan with changed selection writes it, refuse and decline write nothing, applied writes the selection before the journal `begin`, an interrupted journal returns `Outcome::Interrupted` before any write); the lock is held during `decide` (a second acquire inside the closure fails); lock-first ordering (a `Locked` run never reads the journal); supplement rows (PVL cycle 1): `ensure_project_outside_sources` rows (project equal to a source, inside a source, containing a source, a sibling directory whose name shares a prefix with a source is allowed, an uncanonicalizable source is skipped; every refusal happens before the lock, so no `.unam` is created); `unchanged_selection_has_after_text_and_hash_equal_to_before` (G11) and `rollback` after such a run raises no `selection-not-restored`; `execute_refuses_when_the_destination_root_was_swapped_during_the_prompt` is a core-API test in `ac_recovery.rs` (its decide closure swaps `.claude`; there is no CLI twin because integration tests cannot reach the interactive prompt, R8); a `receipt-root-moved` warning appears in `prepare` for a moved project; PVL cycle 2 (Gap 13): `run_registers_the_project_on_every_selection_write` (after a run whose plan is empty but whose selection changed, after an applied run, and after `Edit::Deactivate`, `projects.json` lists the canonical root exactly once; a run that wrote no selection registers nothing; an index forced unreadable by making the index path a directory yields the warning `project-index-unreadable` (the `Ok` branch) while the command still succeeds with the same `Outcome`; a read-only data directory (`chmod 0o500` with the index absent, restored afterwards; the row self-skips under root or off unix) yields the warning `project-index-failed` (the `Err` branch) while the command still succeeds with the same `Outcome`).

## Data Flow (architecture note: primary scenario `unam add a b --yes`)

1. `main` builds `Dirs` from the process environment (including the enterprise directories) and `Ctx` from the flags; `Ctx::load` records whether stdin is a TTY.
2. `cli/change.rs` resolves the root (`--project` or the nearest `.git`), refuses a root that equals, lies inside, or contains a registered source (`ensure_project_outside_sources`, exit 2, before anything is created), takes the project lock (creating `.unam/`, writing the lock line), then asks `apply::inspect` about the journal: absent is clear, a completed leftover is finalized with a note, anything else is exit 10 with nothing changed.
3. `change::prepare` reads the raw `selection.yaml` text, resolves the target and adapter, loads the catalog (cached) and the bundles, applies the edit to the target selection, resolves the result, and splits resolution problems into blocking problems (exit 2, 4, or 5, nothing written) and owned-unreachable carries.
4. It loads the receipt, observes the union of desired and receipted destination names (plus the destination root and shadow candidates), and runs the pure `plan::diff`.
5. Conflicts end the run with exit 6; an empty plan ends it with "no changes" (writing only a changed selection); otherwise the decision closure prints the plan and asks, refuses, or proceeds (`--yes`).
6. On proceed: write `selection.yaml` atomically; `apply::execute` writes the `begin` record (atomic, holds the plan and `receipt_before`), then for each step appends `started`, performs the filesystem work through `FsOps`, appends the terminal record; builds the receipt; writes the history entry, the receipt, the `receipt` marker; deletes the journal; prunes history.
7. The CLI renders the plan, the result, the SES-1 line from the adapter, the SES-2 sentence for removals, the gitignore offer, and exits 0, 7, or the matching error code; the lock drops.

Writes of the whole run, in order: `.unam/lock` (content), `selection.yaml`, `journal.jsonl` (begin, then appended records), destination directories and entries, `history/<op_id>.json`, `applied.json`, journal removal. Reads touch sources only to hash and copy. Nothing runs in the background; there is one process and no network, so the cross-service failure modes reduce to process interruption (journal) and concurrent processes (lock).

## Failure Modes

| Failure | Behavior |
|---|---|
| Another `unam` holds the project | Exit 11 `locked` with the holder pid when readable; nothing written (the lock file content is not touched by the contender) |
| Journal present | Exit 10 `interrupted` with the journal summary; nothing written; `resume` or `rollback` is the cure |
| Journal begin torn or empty | Discarded with a note; the command continues |
| Journal or receipt invalid, crafted, or from a newer version | Exit 1 (`journal-invalid`, `receipt-invalid`, `receipt-version-unsupported`); nothing created or deleted |
| Selection reference unresolved, ambiguous, or invalid | Exit 4, 5, or 2; nothing written; every problem reported as a warning |
| Owned entry's source unreachable | Entry carried with a warning; never removed; an unresolved added reference blocks |
| Conflict (foreign, modified, duplicate name, invalid name, root outside project, root is a file) | Exit 6; nothing written, no selection, no journal |
| Mutating plan without TTY or with `--json`, no `--yes` | Exit 2 `confirmation-required`, plan in the payload, nothing written |
| User declines the prompt | Exit 0 `declined`, nothing written |
| A step fails (copy refused, source changed, IO error, symlink unsupported) | Later steps still run; exit 7; journal kept; next mutating command exits 10 until `resume` or `rollback` |
| A step is skipped (destination modified, foreign, missing, occupied, cross-device) | Nothing deleted; exit 7; ownership released for modified, foreign, missing; journal finalized |
| Crash at any point | State is frozen as written; the next command applies the journal rules; `resume` and `rollback` observe the disk |
| Crash between the receipt write and the journal delete | Detected by `last_op_id` and finalized, never replayed |
| Destination root outside the project or not a directory | Blocking conflict; nothing created or deleted there |
| Cross-device trash rename | `Skipped(CrossDevice)`; nothing moved |
| History prune fails | Warning only |
| Catalog source changed between catalog load and copy | `SourceChanged` step failure; temp directory removed |
| `.unam`, `.unam/<target>`, the lock, `applied.json`, or `journal.jsonl` is a symlink or the wrong kind | Exit 1 `state-dir-invalid` from an lstat check before anything is opened or written; nothing created or modified, nothing outside the project touched |
| Destination root found outside the project or not a directory at apply, resume, or rollback time (swapped after the plan) | Exit 6 `dest-outside-project` or `dest-not-directory` (`DestRootInvalid`) before the first filesystem operation; no journal, directory, or receipt written |
| Project root equals, lies inside, or contains a registered source | Exit 2 `project-overlaps-source` before the lock; nothing written, no `.unam` created |

## Security Review (STRIDE quick scan; vc-security)

| Threat | Surface | Mitigation | Proving test |
|---|---|---|---|
| Spoofing | A crafted journal or receipt claims ownership of a path | Every path rebuilt from the destination root plus a validated single component; removals re-verify the live disk (link text or tree hash); invalid journals rejected whole | `crafted_journal_cannot_escape_the_destination_root`, `remove_owned` unit matrix |
| Tampering | Name escape (`..`, separators), symlinked destination root, symlink swapped between plan and apply | `validate_dest_name`, `join_child`, `classify_dest_root`, `remove_owned` double look, `symlink_dir` never overwrites, copy via temp plus rename | `invalid_skill_name_is_a_blocking_conflict`, `dest_root_symlink_outside_project_is_a_blocking_conflict`, fsops unit matrix |
| Repudiation | Who changed what | History entries with before and after receipt and selection; journal kept on failure | `history_is_capped_at_twenty_entries`, `apply` unit tests |
| Information disclosure | Absolute paths in the receipt and payloads | The receipt lives in `.unam/` (ignored by the offered gitignore lines); payload paths are the user's own | `first_selection_write_offers_gitignore_lines_and_never_writes_gitignore` |
| Denial of service | Torn journal, stuck lock, huge directories | Torn tail tolerated; the lock is an OS lock released on process death (never deleted); hashing only for copy entries | `recovery_tolerates_a_torn_final_journal_line`, `ac_53_*` |
| Elevation | Deleting outside the tool's entries | The only deletions are listed in Safety; `remove_dir_all` confined to one function; a source path can never reach a write function | `remove_dir_all_is_confined`, `source_path_never_reaches_a_write_function`, compile-fail doctest |
| Tampering (state files) | A checked-in `.unam/lock`, `.unam`, or `.unam/<target>` symlink would redirect the lock truncate or a state write outside `.claude/skills` and `.unam` (probed: overwrite and create outside the project) | lstat refusal before open (`state-dir-invalid`), device and inode check after `try_lock` and before truncating | `crafted_state_symlinks_are_refused_and_the_outside_file_is_untouched`, `check_state_layout` and `open_lock_file` unit rows |
| Tampering (destination root swap) | `.claude` swapped for a symlink after the plan, or present at `resume` and `rollback` with a crafted journal | `ensure_dest_root` immediately before the first filesystem operation of `execute`, `resume`, and `rollback`, and once more in `run` after the prompt | `resume_and_rollback_refuse_when_the_destination_root_points_outside_the_project`, `execute_refuses_when_the_destination_root_was_swapped_during_the_prompt` |
| Elevation (source tree as project) | `unam add` run inside the skill library would create state and skills inside a source | `ensure_project_outside_sources` before the lock | `project_root_inside_a_source_is_refused_before_the_lock`, `project_flag_equal_to_a_source_is_refused` |
| Tampering (deletion scope) | A directory named `.DS_Store` with content inside an owned copy was deleted though no hash covered it | The manifest walk uses `SKILL_SKIP_NAMES`; a `.DS_Store` is unlinked only when it is a regular file, anything else is residue | the `remove_owned` `.DS_Store` unit rows |
| Accepted residual windows R1 to R10 | See the Named residuals paragraph of Verification Evidence | R1 double look plus rename-aside and re-hash; R2 narrowed by `ensure_dest_root`; R3 absent-check; R4 identity check; R5 documented; R6 destination-root and single-component confinement; R7 write-ahead `dir` record; R8 `confirm_with` unit tests; R9 reported failed step; R10 bundle-only project invisible to the `source rm` guard (item 26, item 55) | recorded as named residuals, each accepted as a known-gap by the session (no Known-Gap proving strategy is used for any developed behavior) |
